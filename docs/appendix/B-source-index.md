# 附录 B：大牛博客与官方文档索引（与检索手册的关系）

> 定位：本附录**不重复堆链接**（AGENTS.md 已规定链接统一在 `knowledge-retrieval-guide.md` 维护），只放使用说明 + 指向手册的链接 + 贡献三步。

## 概念：为什么需要

写内容、做方案、回答知识性问题时，最大的风险是「来源不权威」。附录 B 是入口页：告诉你「去哪查」和「怎么贡献」，链接本身统一维护在知识检索手册——单一事实源，避免链接散落各章后过期无人维护。

## 动手：怎么用

1. 打开 [知识检索指导手册](knowledge-retrieval-guide.md)
2. 按主题域定位（§1~§8：K8s 核心 / 云原生生态 / 应用打包 / AI 基础设施 / LLM 应用 / K8s 二开 / 架构方法论 / 趋势报告）
3. 按「官方文档 → 官方博客 → 大牛博客」顺序查；版本敏感问题查 KEP（手册 §0.3）；人物与论文见手册 §10 / §11
4. 引用格式照 AGENTS.md：`> 来源：[项目/作者](URL) · 验证环境：…`

## 实用技巧

- 中文来源只用于概念入门，事实/版本/数据回英文官方复核（手册 §0）
- 拿不准的链接标 ⏳ 待验证，不直接采用

## 架构师视角

- 解决什么问题：来源管理——单一事实源，链接不散落、不重复
- 何时用：写任何内容前查来源；贡献新来源时
- 何时不用：无（入口页常驻，按需查阅）
- 权衡：集中维护（更新成本低、口径统一）vs 散落各章（就近方便但易漂移过期）
- 固定三问：平台（手册）提供了什么能力边界？（12 主题域检索表 + 人物表 + 论文锚点）业务接入点在哪？（按主题域查表 + 贡献三步）需要对齐什么？（更新记录写日期）
